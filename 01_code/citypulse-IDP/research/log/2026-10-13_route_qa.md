# Research log, 13 October 2026: route questions on the phone (ADR-035)

Public repository; this entry contains nothing about the confidential passability module.

## Who proposed what (inventorship is human)

| Idea | From |
|---|---|
| Let travellers ask questions about a calculated route, in normal time and in a disaster | The owner (Pragatish N) |
| Run a small model on the phone so that no API is paid for | The owner |
| English and Tamil | The owner |
| Build model-free first (a classifier plus checked templates), then a small model only if it measurably earns its place | The coding agent proposed; the owner agreed ("start with the model-free work") |
| The 18 intents, the fail-toward-refusal handling of safety questions, the bars and kill criteria | The coding agent drafted; the team is to challenge them in review |
| A sealed test set written by the team, not by the agent | The coding agent proposed (the agent's own questions cannot measure the agent's own cue lists) |

## What was done

1. Pre-registration and test-set guide committed first (`data/qa/2026-10-13/`).
2. Dev set of 286 bilingual questions written (agent), used only for development.
3. D0 answerer, tests, ADR-035.

## What was found

- The existing verifier rejected 166 of 432 first-draft answer/situation/language combinations; every rejection was an English sentence opener (or a banned word such as "it works") that rules 2 and 6 cannot ground. Rewording fixed all; the verifier was not changed.
- The cue lists reach 100% on the dev set only because they were adjusted on it. That figure is not a result.
