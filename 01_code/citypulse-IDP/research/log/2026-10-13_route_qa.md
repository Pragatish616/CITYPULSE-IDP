Public repository; this entry contains nothing about the confidential passability module.

## What was done

1. Pre-registration and test-set guide committed first (`data/qa/2026-10-13/`).
2. Dev set of 286 bilingual questions written (agent), used only for development.
3. D0 answerer, tests, ADR-035.

## What was found

- The existing verifier rejected 166 of 432 first-draft answer/situation/language combinations; every rejection was an English sentence opener (or a banned word such as "it works") that rules 2 and 6 cannot ground. Rewording fixed all; the verifier was not changed.
- The cue lists reach 100% on the dev set only because they were adjusted on it. That figure is not a result.

## Open

- A native Tamil reader reviews the Tamil answers and cue lists.
- The team writes and labels the sealed test set (`TEST_SET_GUIDE.md`).
- The target phone is not yet named; latency and memory ceilings are fixed only after that.
- Question box in the app.

Found by building the generator: three real answerer defects the fixed test situations had missed (a sentence opening with "Little", a distance on a rounding boundary, a data-gap and avoided-street overlap). Open: the owner's approval to download a base model and install the training packages; a native Tamil reader; the sealed test set; the phone.
